# 电动汽车库房管理系统使用文档

## 一、系统概述

### 1.1 系统简介
本系统是专为电动汽车行业设计的库房管理系统，用于管理电动汽车相关零部件的库存。系统采用前后端分离架构，支持**普通用户**和**库房管理员**两种角色，通过路由路径区分权限视图。

### 1.2 角色与功能边界

| 角色 | 菜单数量 | 功能说明 |
|------|----------|----------|
| **普通用户** | 2个 | 只能**查看**：零件搜索、出入库记录 |
| **管理员** | 6个 | 完整权限：库存管理、入库/出库操作、补货提醒等 |

### 1.3 主要功能
- **零件管理**：零件的增删改查、分类管理、可见性设置（管理员）
- **库存操作**：零件入库、出库操作（管理员）
- **库存查询**：按关键词、分类等条件搜索零件
- **补货提醒**：自动识别库存低于预警值的零件（管理员）
- **操作记录**：完整记录所有库存操作，支持按类型、分类查询

### 1.4 技术架构
| 层级 | 技术栈 |
|------|--------|
| 前端 | Vue 2.7 + Element UI + Vue Router + Axios |
| 后端 | Spring Boot 2.7 + Java 8 |
| 数据存储 | JSON文件持久化 |
| 开发工具 | Maven、npm |

## 三、系统安装与启动

### 3.1 后端启动步骤

**方式一：使用Maven命令启动**

1. 进入后端项目目录：
```bash
cd backend
```

2. 编译并启动项目：
```bash
mvn spring-boot:run
```

**方式二：打包后运行**

1. 打包项目：
```bash
mvn clean package
```

2. 运行打包后的jar文件：
```bash
java -jar target/ev-warehouse-1.0.0.jar
```

后端服务默认启动在 `http://localhost:8080`

### 3.2 前端启动步骤

1. 进入前端项目目录：
```bash
cd frontend
```

2. 安装依赖：
```bash
npm install
```

3. 启动开发服务器：
```bash
npm run dev
```

前端服务默认启动在 `http://localhost:3001`（端口可能动态分配）

### 3.3 访问系统
启动成功后，在浏览器中访问：

| 角色 | 访问地址 | 说明 |
|------|----------|------|
| 普通用户 | `http://localhost:3001/user/search` | 默认首页 |
| 管理员 | `http://localhost:3001/admin` | 管理员视图 |

**切换视图方式**：点击页面右上角的"切换视图"下拉菜单，可在普通用户视图和管理员视图之间切换。

## 四、普通用户使用指南

### 4.1 功能概览
普通用户只有**两个查看功能**，**没有操作权限**：

| 菜单 | 路由 | 功能说明 |
|------|------|----------|
| 零件搜索 | `/user/search` | 搜索和查看可见零件的库存信息 |
| 出入库记录 | `/user/records` | 查看所有入库出库的历史记录 |

**重要说明**：
- 普通用户**不能**执行入库、出库操作
- 普通用户**没有**补货提醒菜单
- 普通用户只能看到管理员设置为"可见"的零件

### 4.2 零件搜索

1. 进入用户搜索页面：`/user/search`（系统默认首页）

2. 搜索条件：
   - **分类筛选**：可选择电池、电机、轮胎、控制器、玻璃、机油等分类
   - **关键词搜索**：输入零件编号或名称进行模糊搜索

3. 点击"搜索"按钮查看结果，或直接按回车键搜索

4. 搜索结果展示以下信息：
   | 字段 | 说明 |
   |------|------|
   | 零件编号 | 零件唯一标识（如 BAT-001） |
   | 零件名称 | 零件中文名称 |
   | 分类 | 零件所属分类 |
   | 规格 | 零件规格描述 |
   | 库存数量 | 当前库存数量（低于最低库存时红色显示） |
   | 最低库存 | 库存预警阈值 |
   | 单位 | 计量单位（块、台、条、升等） |
   | 状态 | 正常 / 需补货（库存<=最低库存时） |

5. 点击"重置"按钮可清空搜索条件，查看全部零件

### 4.3 查看出入库记录

1. 点击左侧菜单"出入库记录"或访问 `/user/records`

2. 页面顶部显示**出入库汇总**：
   - 总记录数
   - 总入库数量（绿色）
   - 总出库数量（红色）
   - 净变化（入库-出库）
   - 按分类统计的详细列表

3. 可按以下条件筛选记录：
   - **操作类型**：全部 / 入库 / 出库
   - **分类**：按零件分类筛选

4. 点击"查询"按钮查看筛选结果

5. 记录列表展示以下信息：
   | 字段 | 说明 |
   |------|------|
   | 记录编号 | 自动生成的唯一记录号（格式：REC-时间戳-序号） |
   | 操作类型 | 入库（绿色）/ 出库（红色） |
   | 零件编号 | 关联的零件编号 |
   | 零件名称 | 零件中文名称 |
   | 分类 | 零件所属分类 |
   | 数量 | 操作数量（入库显示+，出库显示-） |
   | 单位 | 计量单位 |
   | 库存变化 | 操作前数量 → 操作后数量 |
   | 操作IP | 操作人IP地址 |
   | 操作时间 | 记录创建时间 |

6. 点击"重置"按钮可清空筛选条件，查看全部记录

## 五、管理员使用指南

### 5.1 功能概览
管理员拥有完整的系统权限，共有**6个功能菜单**：

| 菜单 | 路由 | 功能说明 |
|------|------|----------|
| 首页 | `/admin` | 管理员首页（待实现功能占位） |
| 库存管理 | `/admin/parts` | 零件的增删改查、可见性设置 |
| 零件搜索 | `/admin/search` | 搜索所有零件、编辑零件、设置可见性 |
| 入库/出库 | `/admin/stock` | 执行零件入库和出库操作 |
| 出入库记录 | `/admin/records` | 查看所有操作历史记录 |
| 需补货列表 | `/admin/restock` | 查看库存低于预警值的零件 |

### 5.2 库存管理

库存管理是管理员最核心的功能，用于管理所有零件的基础信息。

**访问路径**：`/admin/parts`

#### 新增零件

1. 点击"新增零件"按钮
2. 在弹出的对话框中填写零件信息：

   | 字段 | 必填 | 说明 |
   |------|------|------|
   | 零件编号 | 是 | 唯一标识，如 BAT-001、MOT-001 |
   | 零件名称 | 是 | 中文名称，如"锂离子电池" |
   | 分类 | 是 | 选择：电池/电机/轮胎/控制器/玻璃/机油/其他 |
   | 规格 | 否 | 规格描述，如"50kWh"、"150kW" |
   | 库存数量 | 否 | 初始库存数量，默认为0 |
   | 最低库存 | 否 | 库存预警阈值，默认为0 |
   | 单位 | 是 | 计量单位，如：块、台、条、升、个等 |
   | 可见性 | 否 | 开关控制，开启则普通用户可见 |

3. 点击"确定"保存
4. 系统提示"添加成功"，列表自动刷新

#### 编辑零件

1. 在零件列表中找到目标零件
2. 点击"编辑"按钮
3. 修改需要更新的字段（零件编号不可修改）
4. 点击"确定"保存

#### 删除零件

1. 在零件列表中找到目标零件
2. 点击"删除"按钮
3. 在确认对话框中点击"确定"

   **注意**：删除操作不可恢复，请谨慎操作！

#### 设置可见性

在库存管理页面中，每个零件都有一个"可见性"开关：

- **开启**（蓝色）：该零件对普通用户可见
- **关闭**（灰色）：该零件仅管理员可见

切换开关后系统自动保存设置。

### 5.3 零件搜索（管理员）

**访问路径**：`/admin/search`

管理员的零件搜索功能比普通用户更强大：

1. 搜索方式与普通用户相同（按分类、关键词搜索）
2. 搜索结果额外显示：
   - **可见性状态**：显示"可见"或"隐藏"标签
   - **操作列**：包含"编辑"和"隐藏/显示"按钮

3. 快捷操作：
   - 点击"编辑"可直接修改零件信息
   - 点击"隐藏"可将零件设置为对普通用户不可见
   - 点击"显示"可将零件设置为对普通用户可见

### 5.4 入库/出库操作

这是管理员执行库存变动的核心功能。

**访问路径**：`/admin/stock`

#### 入库操作

1. 选择操作类型：**入库**
2. 选择零件：在下拉列表中选择需要入库的零件
3. 输入入库数量（必须大于0）
4. 点击"确定"按钮
5. 系统提示"入库成功"，库存数量增加

#### 出库操作

1. 选择操作类型：**出库**
2. 选择零件：在下拉列表中选择需要出库的零件
3. 输入出库数量（必须大于0，且不能大于当前库存）
4. 点击"确定"按钮
5. 系统提示"出库成功"，库存数量减少

**重要**：
- 入库/出库操作会自动记录操作人IP地址
- 所有操作都会在"出入库记录"中留下历史记录
- 出库时系统会检查库存是否充足，不足则无法出库

### 5.5 出入库记录（管理员）

**访问路径**：`/admin/records`

功能与普通用户的出入库记录相同，可查看所有操作历史记录。

### 5.6 需补货列表

**访问路径**：`/admin/restock`

系统自动识别库存数量低于最低库存预警值的零件，管理员可在此页面统一查看和处理。

页面展示：
- 零件编号、名称、分类
- 规格、当前库存、最低库存
- 单位、状态（均为"需补货"）

**补货建议**：根据当前库存与最低库存的差额，及时安排采购补货。

## 七、数据说明

### 7.1 数据存储位置
系统数据以JSON文件格式存储在 `backend/data/` 目录下：
- `parts.json`：零件数据
- `records.json`：库存操作记录

**数据持久化机制**：
- 系统启动时自动从JSON文件加载数据
- 每次数据变更（新增、修改、删除、入库、出库）后自动保存到文件
- 如果数据文件不存在，系统自动初始化示例数据

### 7.2 零件数据结构
```json
{
  "id": "BAT-001",
  "name": "锂离子电池",
  "category": "电池",
  "specification": "50kWh",
  "quantity": 100,
  "minStock": 20,
  "unit": "块",
  "visible": true
}
```

字段说明：
| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 零件编号，唯一标识 |
| name | String | 零件名称 |
| category | String | 分类 |
| specification | String | 规格描述 |
| quantity | Integer | 当前库存数量 |
| minStock | Integer | 最低库存预警值 |
| unit | String | 计量单位 |
| visible | Boolean | 是否对普通用户可见 |

### 7.3 库存记录数据结构
```json
{
  "id": "REC-20240101120000-0001",
  "partId": "BAT-001",
  "partName": "锂离子电池",
  "category": "电池",
  "type": "入库",
  "quantity": 10,
  "unit": "块",
  "beforeQuantity": 90,
  "afterQuantity": 100,
  "ipAddress": "127.0.0.1",
  "createTime": "2024-01-01T12:00:00.000+0000"
}
```

字段说明：
| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 记录编号（自动生成） |
| partId | String | 关联的零件编号 |
| partName | String | 零件名称（冗余存储） |
| category | String | 分类 |
| type | String | 操作类型："入库" 或 "出库" |
| quantity | Integer | 操作数量 |
| unit | String | 计量单位 |
| beforeQuantity | Integer | 操作前库存 |
| afterQuantity | Integer | 操作后库存 |
| ipAddress | String | 操作人IP地址 |
| createTime | Date | 操作时间 |

### 7.4 示例数据
系统首次启动时会自动初始化18个示例零件，涵盖以下分类：

| 分类 | 示例零件 |
|------|----------|
| 电池 | 锂离子电池(50kWh/75kWh)、磷酸铁锂电池(100kWh) |
| 电机 | 永磁同步电机(150kW/200kW)、异步电机(120kW) |
| 轮胎 | 子午线轮胎(225/55 R18/235/60 R19)、防爆轮胎 |
| 控制器 | 整车控制器(VCU-100)、电机控制器(MCU-200)、电池管理系统(BMS-300) |
| 玻璃 | 前挡风玻璃、后挡风玻璃、侧窗玻璃 |
| 机油 | 齿轮油(75W-90)、防冻液(-40℃)、刹车油(DOT4) |

## 八、API接口说明

### 8.1 接口权限说明

| 接口组 | 前缀 | 权限 | 数据范围 |
|--------|------|------|----------|
| 通用接口 | `/api/parts` | 无限制 | 所有数据 |
| 用户接口 | `/api/user/*` | 普通用户 | 仅可见数据 |
| 管理员接口 | `/api/admin/*` | 管理员 | 所有数据 |

### 8.2 用户接口（普通用户使用）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/user/parts` | 获取可见零件列表 |
| GET | `/api/user/parts/{id}` | 获取单个可见零件详情 |
| GET | `/api/user/parts/search` | 搜索可见零件（支持keyword和category参数） |
| GET | `/api/user/parts/need-restock` | 获取可见的需补货零件 |
| POST | `/api/user/parts/stock-in` | 入库操作 |
| POST | `/api/user/parts/stock-out` | 出库操作 |
| GET | `/api/user/records` | 获取库存记录（支持type、category、partId参数） |
| GET | `/api/user/records/summary` | 获取记录统计汇总 |

### 8.3 管理员接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/parts` | 获取所有零件列表 |
| GET | `/api/admin/parts/{id}` | 获取单个零件详情 |
| POST | `/api/admin/parts` | 新增零件 |
| PUT | `/api/admin/parts/{id}` | 更新零件 |
| DELETE | `/api/admin/parts/{id}` | 删除零件 |
| PUT | `/api/admin/parts/{id}/visibility` | 更新零件可见性 |
| GET | `/api/admin/parts/search` | 搜索零件 |
| GET | `/api/admin/parts/need-restock` | 获取需补货零件 |

### 8.4 库存记录接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/records` | 获取库存记录（支持type、category、partId筛选） |
| GET | `/api/records/summary` | 获取记录统计汇总 |

### 8.5 统一响应格式

所有API接口返回统一的JSON格式：

```json
{
  "success": true,
  "message": "操作成功",
  "data": { ... }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| success | Boolean | 操作是否成功 |
| message | String | 响应消息 |
| data | Object/Array | 响应数据（失败时为null） |

## 九、常见问题

### Q1: 如何修改后端服务端口？
修改 `backend/src/main/resources/application.properties` 中的 `server.port` 配置：
```properties
server.port=8080
```

### Q2: 如何修改数据存储目录？
修改 `backend/src/main/resources/application.properties` 中的 `data.directory` 配置：
```properties
data.directory=./data
```

### Q3: 前端如何配置后端API地址？
修改 `frontend/vue.config.js` 中的代理配置：
```javascript
devServer: {
  port: 3000,
  proxy: {
    '/api': {
      target: 'http://localhost:8080',  // 后端地址
      changeOrigin: true
    }
  }
}
```

### Q4: 数据会丢失吗？
系统会在每次数据变更后自动保存到JSON文件，正常关闭服务不会丢失数据。建议定期备份 `backend/data/` 目录。

### Q5: 如何重置数据？
删除 `backend/data/` 目录下的 `parts.json` 和 `records.json` 文件，重启系统后会重新初始化示例数据。

**警告**：此操作会清空所有业务数据，请谨慎操作！

### Q6: 普通用户和管理员如何切换？
点击页面右上角的"切换视图"下拉菜单，选择：
- "普通用户视图" → 切换到 `/user/search`
- "管理员视图" → 切换到 `/admin`

### Q7: 为什么普通用户看不到某些零件？
管理员在库存管理中可以设置零件的"可见性"：
- 可见性开关**开启**：普通用户可见
- 可见性开关**关闭**：仅管理员可见

### Q8: 如何查看谁执行了入库/出库操作？
在"出入库记录"页面，每条记录都有"操作IP"字段，记录了操作人的IP地址，可用于追踪操作来源。
